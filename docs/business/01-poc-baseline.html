Bolo Bill — PoC baseline and evidence register

What exists, what has been proven, and what has not. Everything downstream cites this page. Written to be handed to a diligence process unedited.

1. What the PoC actually does

A voice-first billing web app running on a shopkeeper's own Android phone. The shopkeeper speaks; the bill assembles line by line; a UPI QR carrying the exact amount is shown; a numbered receipt is produced.

2. Stack as built

ASR: Sarvam saarika:v2.5, cloud, per-utterance, per-shop language code.
Understanding: a deterministic grammar parser. No LLM anywhere in the utterance path. Chosen because a grammar's failures are legible — when it cannot parse, it knows, and that feeds the confidence gate. A model that always returns something confident is the exact failure mode this product cannot afford.
Backend: Python/FastAPI on Vercel serverless · Supabase Postgres over PostgREST.
Client: vanilla-JS PWA, Material 3 tokens. Chrome Web Speech API for wake-word spotting; Web Bluetooth for ESC/POS.
Languages: Tamil, English, Hindi, Malayalam, Telugu, Kannada — code-mixed, per shop. Numerals, units, aliases and phonetic rules are data files, not code.

The silent-error work is the strongest technical signal. Three real defects found and fixed: ₹115 of goods billing as ₹12.50 (multi-item collapse); 500g of a ₹50/kg item billing ₹25,000 (unit mismatch); 300g of onion billing ₹0.07 (unrecognised numeral). Each was silent. Each is now a regression test. This is the discipline the product's core promise depends on.

5. What this baseline means for the raise

This is a working prototype with one live design partner, not a pilot with traction. Positioned honestly it is still a strong pre-seed artifact: six languages, a tested grammar, a real receipt series and a live URL, built solo. Positioned as traction it will not survive a technical diligence call.

The two questions a competent investor asks first are the two in the register above: what does an utterance cost you, and does it work in a loud shop with someone else's voice. The roadmap must answer both, and the funding ask should be visibly sized to do so.
